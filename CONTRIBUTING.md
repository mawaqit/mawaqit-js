# Contributing

## Setup

Install [Node.js](https://nodejs.org) 24 and [pnpm](https://pnpm.io), then:

```sh
pnpm install
```

## Checks

The CI runs all of them, on Node.js 22, 24 and 26, Deno and Bun:

```sh
pnpm test                # unit and type tests, 100% of lines and branches
pnpm test:live           # against the real API, with MAWAQIT_TOKEN for most tests
pnpm lint                # Biome; `pnpm format` fixes what it can
pnpm typecheck           # strict TypeScript
pnpm build               # dist/, without Node.js types
pnpm check:package       # publint and Are The Types Wrong, after the build
pnpm check               # all of the above but the live tests
```

The tests import the package by its name, `@mawaqit/sdk`: the `@mawaqit/source` condition of its
`exports` resolves it to `src/`, without a build.

## How the code is organized

Most of the code is generated from the OpenAPI description of the API, which lives in the private
[mawaqit/api-spec](https://github.com/mawaqit/api-spec) repository.

| Path | Written by |
| --- | --- |
| `src/types.ts` | The generator: the response types, from the schemas. |
| `src/resources/` | The generator: one class per tag, one method per operation. |
| `src/client.ts` | The generator: the client and its resources. |
| `tests/examples/` | The generator: real API responses, copied from the spec. |
| `src/core.ts` | Hand: requests, authentication, retries, logs. |
| `src/errors.ts`, `src/hijri.ts`, `src/prayer-times.ts`, `src/dates.ts`, `src/index.ts` | Hand. |
| `codegen/generate.ts` | Hand: the generator. |

Generated files start with `// Generated by codegen/generate.ts`: never edit them, change the spec
or the generator instead.

## Changing the API

1. Change the spec in mawaqit/api-spec and tag a new version.
2. Pin it here and regenerate the code. This needs the [GitHub CLI](https://cli.github.com),
   logged in with access to the spec:

   ```sh
   pnpm codegen --pin v0.5.0
   ```

3. Add tests, and commit the generated files with `codegen/spec.json`.

`pnpm codegen` alone regenerates the code from the pinned spec, and `--spec-dir ../api-spec` reads
a checkout of it. The `Codegen` workflow checks that the committed code matches the pinned spec,
reading it with the `API_SPEC_DEPLOY_KEY` secret of the `api-spec` environment: a read-only deploy
key of mawaqit/api-spec.

## Releasing

1. Bump the version in `package.json` and `src/version.ts`, and move the changes of `CHANGELOG.md`
   under the new version.
2. Publish a GitHub release whose tag is the version, like `1.0.0`.

`release.yml` then runs the CI and publishes to npm with trusted publishing and provenance. Mark
prereleases, like `1.0.0-beta.2`, as pre-releases: they are published with the `next` tag, which
`npm install` only installs when asked for.
